# Failure scenarios and recovery direction

These scenarios describe expected failure handling for the reconstructed
architecture. They are design guidance, not evidence that the failures have
been exercised in AWS. Recovery directions intentionally stop short of
inventing monitoring or automation that is not implemented.

| Scenario | Symptom | Likely cause | Blast radius | Detection | Safe recovery / rollback |
| --- | --- | --- | --- | --- | --- |
| Wrong management-account credentials | Organization, account-vending, or bootstrap operations fail authorization or target the wrong account. | Ambient credentials are not the Organizations management account. | Organization governance, account creation, trusted access, or delegated-admin state. | Review caller identity and provider/account context before any mutation. | Stop. Correct operator/CI authentication, re-render, and review the plan. Do not repair by broadening permissions. |
| Wrong Log Archive credentials | Storage fails or creates custody resources in the wrong account. | Ambient credentials do not target Log Archive. | Audit-log custody, S3, and KMS ownership. | Confirm provider context and planned account before apply. | Stop before mutation; correct authentication and re-plan. If already created, preserve evidence and recover through the owning state. |
| Account creation fails or email is duplicated | `aws_organizations_account` creation fails or AWS rejects an owner email. | Email is already associated with an AWS account, account limit, invalid OU, or AWS-side asynchronous failure. | The affected account and downstream dependencies; other accounts may remain independent. | Terraform error, AWS Organizations account status, and dependency output availability. | Do not reuse a real email blindly. Resolve the AWS-side cause, verify the intended OU and email, and retry only the affected lifecycle boundary. |
| Trusted access is absent | Delegated-admin registration fails with `CloudTrailAccessNotEnabledException`. | CloudTrail trusted access was not enabled first. | CloudTrail bootstrap and later trail management. | Bootstrap error and management-account Organizations state. | Enable trusted access from the management account, verify it, then retry delegated-admin registration. |
| Delegated admin runs before trusted access | Registration is rejected or the expected CloudTrail control plane is unavailable. | Dependency/order was bypassed or state was applied manually out of order. | CloudTrail administration; no trail should be assumed operational. | Terragrunt dependency graph and AWS delegated-admin status. | Restore the approved order: trusted access, delegated admin, then trail. Do not continue with trail mutation. |
| Organization outputs or state are missing | Downstream OU IDs, organization IDs, or management-account IDs are unavailable; mocks may appear during validation. | Upstream state has not been applied, cannot be read, or remote state is not configured. | Account vending, storage, and downstream CloudTrail composition. | Terragrunt dependency resolution and mock-output warnings. | Use mocks only for validation. Restore authoritative upstream state before any apply and keep state boundaries separate. |
| S3 bucket-name collision | Log Archive storage cannot create the bucket. | The caller-supplied global S3 name is already taken or invalid. | Storage unit only until a valid name is supplied; trail creation must wait. | S3/Terraform error and composition input review. | Choose a new operator-supplied globally unique name, update composition, and revalidate policy/trail inputs. Do not hardcode a personal or company name. |
| KMS policy mismatch or disabled key | CloudTrail exists but encrypted log delivery fails. | `SourceArn`, encryption-context, service-principal, or key state is incorrect. | Future audit delivery and potentially organization-wide evidence coverage. | KMS key state, CloudTrail delivery/status checks, and missing objects/digests. | Restore the narrowly scoped approved key policy or key state, then verify new delivery. Do not grant broad workload `kms:Decrypt`. |
| CloudTrail cannot deliver logs | Trail is present or logging is enabled, but objects do not arrive in Log Archive. | Bucket policy, ACL/ownership semantics, KMS permissions, or trail configuration is incorrect. | Central audit coverage across the organization. | CloudTrail status/errors and absence of expected log/digest objects. | Stop promotion, correct only the required S3/KMS/trail configuration, and verify delivery before treating the trail as operational. |
| SCP is attached too broadly | Valid account, region, logging, security, or recovery actions are denied. | A restrictive policy was attached outside the staged rollout or inherited scope was misunderstood. | All principals in affected member accounts, subject to SCP semantics. | Policy effective-permission tests, service errors, and attachment/inheritance review. | Roll back only the affected attachment, restore the prior approved policy state, record the failure, and return through Policy-Staging. |
| Region restriction blocks a required global/control-plane API | A required operation is denied or an allowed API has an unexpected cross-Region effect. | Exception list is incomplete or `aws:RequestedRegion` behavior was assumed to be a complete residency control. | Affected governed account workflows; potentially security or recovery operations. | Staged AWS tests and API error analysis. | Remove or narrow the staged attachment, validate the service behavior, and review the fixed exception list deliberately. Do not silently add a wildcard exception. |
| State loss or partial apply | Terraform cannot reconcile ownership, or some units have applied while dependencies remain incomplete. | State was lost, backend is unavailable, or a multi-unit execution stopped partway through. | The affected state boundary and any downstream dependency chain. | State/backend review, Terraform refresh/plan, and Terragrunt execution result. | Stop downstream changes, recover state from an approved backup when available, inspect actual AWS state, and reconcile one boundary at a time. Do not recreate resources blindly. |
| Units applied out of dependency order | A downstream plan fails, uses unavailable outputs, or targets incomplete infrastructure. | Operator bypassed Terragrunt dependencies or ran units manually in the wrong sequence. | The downstream unit and any partially changed resources. | Dependency graph review and missing-output/provider errors. | Restore the order encoded in composition, verify upstream state, and re-plan the affected unit before mutation. |

The architecture does not currently include remote-state recovery automation,
CloudTrail alerting, SCP rollout automation, or cross-account identity
verification. Operators must provide those controls before treating the design
as an operationally complete landing zone.
